# 実装計画（段階0-a〜3-b）

docs/handoff/SPEC.md と IMPLEMENTATION.md にもとづく短い計画です。1回の指示で1段階だけを進め、段階ごとにPull Requestを作って止まります。

| 段階 | 作るもの | 完了の確認 |
|---|---|---|
| 0-a | handoff資料の移動、.gitignore、DECISIONS.md、config/ の設定例、schemas/（設定・データのJSON Schema）、検証CLI `python -m collector.validate`、README | スキーマ検証のテスト（pytest）が通る |
| 0-b | demo/ に架空記事20件程度（日付不明、本文未取得、AI未要約、タグ修正あり、2版あり）、架空の実行履歴と取得状況。画面用JSONへの公開用変換（allowlist、最終タグ＝AIタグ＋追加－除外）。.env や .cache/ の混入検査 | 許可項目以外（原文全文、API生応答、タグ候補、秘密値）が出力されないテストが通る |
| 1-a | web/ に TypeScript＋Vite の静的画面：最新一覧、絞り込み（タグ・機関・期間）、文字検索、記事詳細（AIタグと人の修正を区別）、demo時の「架空データ」表示、XSS対策。Windows PowerShell向けの起動手順 | ローカル起動して架空データと分かる表示を確認 |
| 1-b | タグ別Wiki、週次レポート（画面とMarkdown）、取得状況画面（古いデータの警告）、修正依頼リンク、サブパス対応のbaseとhashルーティング、JSON/CSVエクスポート | ビルド成功、ビルド結果をサブパスで開き直リンクを確認 |
| 2-a | collector/ にRSS・HTML一覧・テキストPDFの収集（fixtureのみ、実サイトへはアクセスしない）。URL正規化、許可ホスト検証、本文hashでの新規・変更・既存判定、版の追加、日付の根拠と精度、--start/--end、情報源ごとのstate、部分失敗時に成功地点を進めない、再試行対象 | 重複・日付境界・日付不明・本文変更・ナビだけの変化・部分失敗・0件警告のテストが通る |
| 2-b | 公的機関サイトへの接続確認、こども・母子保健の情報源候補の提示 →（選定を待つ）→ 採用した情報源で各5件程度を実取得、再実行で重複しないことの確認、release_mode=real で画面表示 | 実記事の出典・日付根拠・取得状況を画面で確認 |
| 3-a | AI要約・タグ付けを1つのproviderで実装（実APIは呼ばずモックでテスト）。出力のJSON Schema検証、登録外タグの拒否、本文を信頼できないデータとして区切る、キャッシュキー、件数・トークン・再試行の上限、使用量記録、APIキー設定手順 | 正常・JSON異常・登録外タグ・APIエラー・上限超過・キーなし・タグ修正の維持のテストが通る |
| 3-b | 件数と概算費用を示して承認を待つ → 承認後に2-bの記事を実APIで処理、原文との照合結果、使用量と費用の記録、タグ候補の一覧 | 承認後の実行と照合結果の報告 |

## 技術の分担

- Python（収集・AI処理・検証・公開用変換）：クラウド環境で実行する。PCでは不要。
- Node.js（画面のビルドと表示）：PCで画面を見るときに必要。
- データ：config/（人が編集）と data/（自動生成）を分け、どちらも schemas/ のJSON Schemaで検証する。
