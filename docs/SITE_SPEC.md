# 外部環境情報サイト 仕様書（現行版）

作成日 2026年10月7日。内容は、リポジトリの `main`（Pull Request 22 まで反映）の実装に基づく。
開発時の要求仕様は `docs/handoff/SPEC.md`、設計判断の経緯は `docs/DECISIONS.md` を参照。この文書は「いま動いているもの」の説明で、図入りの概要は `docs/site_overview.html`（ブラウザで開く）にある。

## 1 目的と位置づけ

- 中央官庁・公的機関などの公開情報を定期的に集め、短い概要と登録済みタグを付けて、最新一覧とテーマ別Wikiで閲覧できるようにする。
- 個人の検証版であり、部署の公式な成果物ではない。公開されたWebページはインターネット上で誰でも見られる。
- 扱うのは公開情報と一般的な分類タグだけ。自社製品の評価、重要度・優先度、内部メモ、顧客・案件情報は扱わない（要求仕様 3章）。
- 収集と要約は通常のプログラムで実行する。Claude Code は開発を支援するだけで、運用時には動かない。

## 2 全体の構成

| 層 | 役割 | 場所 |
|---|---|---|
| 設定 | 人が決める。情報源、タグ、AI、サイト表示、人によるタグ修正 | `config/`（`sources.yaml`、`tags.yaml`、`ai.yaml`、`site.yaml`、`tag_overrides.yaml`） |
| 収集 | 一覧と本文（添付PDFを含む）を取得し、記事と版を保存 | `collector/collect.py`、`fetch.py`、`extract.py`、`dates.py` |
| AI要約 | 概要・論点・日付・タグを生成し、検証して保存 | `collector/summarize.py`、`ai_provider.py` |
| ルールタグ | キーワード一致でタグを付ける（AIは使わない） | `collector/rule_tags.py` |
| 自動生成データ | 収集・要約の結果。人は直接編集しない | `data/`（`articles/`、`summaries/`、`runs/`、`state.json`、`rule_tags.json`、`tag_candidates.json`） |
| 公開用変換 | 許可した項目だけを画面用JSONにする（allowlist） | `collector/export.py` → `web/public/data/` |
| 週次レポート | 期間ごとのMarkdownとJSON | `collector/report.py` → `reports/` |
| 画面 | TypeScript/Vite の静的サイト。1ファイル版も作る | `web/`、`viewer/info_viewer.html` |
| 自動実行 | 毎週の更新とPages公開 | `.github/workflows/weekly-update.yml` |

データは一方向に流れる：設定 → 収集 → AI要約・ルールタグ → 公開用変換 → 画面。ブラウザが読むのは公開用変換の出力だけで、`data/` の生データや原文は読まない。

## 3 情報源

採用中の情報源（`config/sources.yaml` の `enabled: true`）：

| 情報源 | 取得方式 | 備考 |
|---|---|---|
| こども家庭庁（新着・更新） | HTML一覧 | 添付PDFも読む |
| こども家庭センターポータルサイト（新着情報） | HTML一覧 | 会員限定ページは題名・日付のみ（本文は取得しない） |
| 5歳児健診ポータル（トピックス） | HTML一覧 | |
| CMIC Trust 株式会社（NEWS） | サイトマップ＋ページ内データ | 全記事に「ベンダ動向」を設定で付与 |
| 母子モ株式会社（プレスリリース、PR TIMES） | HTML一覧 | 同上 |
| 株式会社ミラボ（ニュース） | HTML一覧 | 同上 |
| 株式会社両備システムズ（ネウボラかるてに関する部分） | HTML一覧 | 同上 |

- 取得方式は `rss`、`html`、`sitemap`、`manual`。
- 民間企業3社と両備システムズは、ユーザーが個別に認めたもの。他の民間企業は対象にしない。
- 採用していない候補（厚生労働省、国立成育医療研究センター、デジタル庁、内閣府など）は `enabled: false` で登録済み。調査結果は `docs/SOURCES.md`。
- 情報源ごとに、許可ドメイン、一覧の探索範囲、取得上限、添付PDFの扱い（最大3件・30ページ・12MB）、リンクの除外規則、`login_required`、`fixed_tags`、外部連携用の `csv_id`・`publisher`・`source_type` を設定できる。
- 公開されている個人名は、表示・要約してよい（ユーザー判断）。

## 4 収集の仕様

- 実行は週1回（毎週日曜 日本時間15時。GitHub Actions）。手動実行はGitHubの「Actions」タブからだけで、公開画面に実行ボタンはない。
- 週次の収集範囲は、情報源ごとに「前回の成功日の14日前から今日まで」。重複確認と、既存記事の変更検知のため。
- 記事は一覧のURLから識別し、再実行しても重複しない。本文が変わったら新しい「版」として保存し、過去の版は消さない。
- 部分失敗のとき、成功した情報源の分は保存し、失敗した情報源の成功地点は進めない。全情報源が失敗したときは何も保存・公開しない。
- 日付が不明、本文が未取得、AI処理が失敗した場合は、成功や「該当なし」に変換せず、そのまま状態として記録・表示する。
- 公開日は、日まで分かるものだけを日付として扱う（日付と時刻つきの値は日本時間の日付にする。月だけ・年だけ・不明は「日付不明」）。日付の根拠（引用や取得方法）を保存する。
- 本文の全文は `.cache/`（Gitに入れない）にだけ置く。Gitに入るのは、版の記録、ハッシュ、短い根拠の引用だけ。

## 5 AI要約とタグ

- 既定のモデルは `claude-sonnet-5-5`（`config/ai.yaml`）。APIキーは環境変数 `INFO_AI_API_KEY`（GitHubでは Secrets）から読み、リポジトリ・ログ・画面には出さない。
- 出力：日本語の概要（150〜200字前後）、主要な論点（5つまで）、対象者・対象機関、確認できた日付、確認できなかった点、タグと理由。出力の形はスキーマで検証し、誤りは再試行（最大2回）、それでも失敗したら「失敗」として記録する。
- 1記事の本文は先頭2万文字まで。1回の実行で記事60件、入力100万トークンまでの上限がある。上限を超えた記事は「未処理」として止める。
- 費用の目安は1件あたり約$0.024。AIを呼ぶのは、新規または本文が変わった記事だけ（記事の内容・モデル・指示文・タグ定義が同じなら再利用）。
- 実行前に、課金されない方法でAPIキーが使えるかを確認する。

### タグの付き方

| 由来（画面の表示） | 付け方 |
|---|---|
| AI | 登録済みタグから、AIが理由つきで選ぶ。`rule_only` のタグは選べない |
| 設定 | 情報源の `fixed_tags`（その情報源の全記事に付ける）。ベンダ動向に使う |
| 一致 | `config/tags.yaml` の `auto_rules`（キーワードの正規表現）に題名・本文が一致 |
| 人が追加／取り消し線 | `config/tag_overrides.yaml` に書いた記事ごとの修正。再処理で書き換えない |

- 登録済みタグ（`config/tags.yaml`）：母子保健、子育て支援、制度改正、補助金・交付金、通知・事務連絡、自治体DX・標準化、調査・統計、審議会・検討会、ベンダ動向（`rule_only`）。
- AIが提案した新しいタグ候補は `data/tag_candidates.json` に記録するだけで、`tags.yaml` へは自動追加せず、画面にも出さない。
- 自社の関心や判断が読み取れるタグ（特定製品への影響、営業機会、要対応など）は作らない。

## 6 画面

URLの `#` 以降で画面が切り替わり、どの画面もブックマーク・共有できる。

| 画面 | URL | 内容 |
|---|---|---|
| 最新情報 | `#/` | 直近7日（最終収集日を含む。`latest_days`）に公開日が入る記事だけ。公開日が不明な記事は表示せず、除いた件数を示す。ページ送りあり（50件。`page_size`） |
| 記事を探す | `#/search` | 全期間をタグ・機関・期間（公開日）で絞り込み、文字検索（空白区切りは「すべてを含む」）。結果をCSV・JSONで保存できる |
| 記事詳細 | `#/articles/<id>` | 出典リンク、公開日・更新日・取得日と日付の根拠、概要、論点、対象、確認できた日付、確認できなかった点、添付資料の読み取り状況、タグと由来・理由、AI処理状態、版の履歴 |
| Wiki | `#/wiki`、`#/wiki/<タグ>` | タグごとの説明と、該当記事を公開日の年月ごとに新しい順で表示 |
| 週次レポート | `#/reports`、`#/reports/<期間>` | 7日ごとの期間を選び、新規・変更の記事、タグ別件数、情報源別の取得状況。日付不明の記事は数えず、除いた件数を示す。Markdown・CSVで保存できる |
| 取得状況 | `#/status` | 最終実行、情報源ごとの成否・失敗理由・探索範囲、日付不明・本文未取得・未要約の件数、実行履歴。データが古い（8日超）ときや失敗が続くときは注意を出す |
| 情報源 | `#/sources` | 収集中の情報源と候補の一覧、取得方式、制約・メモ |

- すべての画面に「独自に作成した概要で、必ず出典で確認すること」を表示する。AIが付けた概要・タグには「AI」の表示を付ける。
- 右上に修正依頼のリンクがある。URLは `config/site.yaml` の `correction_request_url`（今は未設定で「未設定」と表示）。
- ブラウザからの編集、収集の実行、認証はない。タグや情報源の変更は、設定ファイルの編集（Claude Codeへの依頼）で行う。
- 画面は、公開用サイト（GitHub Pages）と、1ファイルのHTML（`viewer/info_viewer.html`。ダブルクリックで開ける）の2通りで見られる。

## 7 出力

| 出力 | 場所・操作 | 内容 |
|---|---|---|
| 記事一覧のCSV・JSON | 「記事を探す」の保存ボタン | 絞り込んだ結果。Excelで開ける |
| 週次レポート（Markdown） | 「週次レポート」の保存ボタン、`reports/` | 新規・変更、タグ別件数、取得状況 |
| 外部連携用CSV | 「週次レポート」の「CSVで保存」 | 別システムへ渡す固定15列（下記） |

### 外部連携用CSV

- 行：選択中の週の新規と変更の記事（既定は最新の週）。公開日の新しい順。公開日が日まで分からない記事は含めない。
- 形式：UTF-8（BOM付き）、カンマ区切り、改行CRLF、ファイル名 `external_news_YYYYMMDD_HHmm.csv`。セル先頭が `= + - @` などの場合は `'` を前置する。
- 列：`record_id`（`{csv_id}_{公開日YYYYMMDD}_{連番3桁}`）、`source_id`（情報源の固定ID）、`publisher`、`title`、`url`、`published_date`、`updated_date`、`fetched_at`（日本時間）、`source_type`（news／press_release／notice_pdf／dashboard）、`content_hash`、`category`（タグ名を半角スラッシュでつなぐ）、`excerpt`（独自の要約と論点。1000字まで）、`source_list_url`、`hash_status`、`hash_scope`。
- `content_hash`：題名と本文を正規化したSHA-256（小文字16進64桁）。本文を取得できない記事は空欄で、`hash_status` は `unavailable`。
- 形式のひな形：`docs/csv/external_news_template.csv`（架空の3行）。

## 8 自動更新と公開

毎週の流れ（`weekly-update.yml`）：

1. 設定とデータを検証 → 2. AIのAPIキーを確認（無料） → 3. 収集 → 4. AI要約 → 5. ルールタグ → 6. 画面用データと週次レポートを作成 → 7. 画面のテストと1ファイル版の作成 → 8. pytest → 9. 秘密値・原文の混入を検査 → 10. `data/` などを `main` へコミット → 11. その内容で画面を作り、GitHub Pagesへ公開。

- 要約だけが失敗したときも、収集できた記事は「未要約」として公開し、最後にAction全体を赤にして知らせる。
- 同時に2つは動かさない。使うActionは固定版（checkout v7、setup-python v7、setup-node v7、upload-pages-artifact v5、deploy-pages v5）。

## 9 安全の仕組み

- 画面用データは allowlist で変換し、スキーマ（`schemas/`）で検証する。秘密値、原文全文、AIの生応答、タグ候補はブラウザに渡さない。
- コミット前とActionsで `scripts/check_repo_safety.py` が、秘密値・`.env`・`.cache/` が含まれていないかを検査する。
- 画面側は、文字列をHTMLとして挿入しない（許可した属性だけ）。
- リポジトリは公開で、履歴も公開される。Gitに入れるものはすべて公開されると考える。

## 10 テスト

| 種類 | 内容 | 実行 |
|---|---|---|
| Python（pytest、362件） | 収集・抽出・日付・要約・タグ・変換・レポート・ハッシュ・スキーマ・安全検査など | `python -m pytest -q` |

## 11 既知の制限

- すべての記事を取得できているとは限らない。一覧に残っている範囲だけが対象で、過去の完全な復元は保証しない。情報源ごとの取得範囲は「取得状況」「情報源」画面で確認できる。
- 画像だけのPDFは読めない。添付は1記事3件・30ページ・12MBまで。長い本文は先頭2万文字だけを要約に使う。
- AIの要約・タグは誤ることがある。原文と照合した少数件では事実の誤りはなかったが、保証にはならない。タグの付け方には揺れがある。
- Actionsの実行環境には `.cache/`（本文）が残らない。そのため、収集範囲より古い未要約の記事は、Actions上では要約できない。
- 週次レポートは直近12週までを画面に出す。
- 費用（AI API）は個人負担の従量課金で、無料で恒久運用できるとは約束しない。
- 修正依頼のリンクは未設定。
- ハッシュは、添付PDFの読み取り上限を変えると変わる。`category` は、AIとルールによるタグの揺れを引き継ぐ。
